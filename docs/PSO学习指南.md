## 一、先建立画面，再碰公式

不要从公式开始。先在脑子里放一部动画：

> 一群鸟在一片山里找食物。山的高度就是目标函数值，越低越好。
> 每只鸟看不见整座山，它只能做三件事：
> 1. **凭惯性继续飞** —— 我刚才朝这个方向飞，那就再飞一会儿；
> 2. **回想自己去过的最好地方** —— 我记得那边草多一点，往那边靠一靠；
> 3. **看看同伴在哪找到好东西** —— 大家公认最好的那个点，我也往那边靠。

**这三件事就是 PSO 的全部。** 没有梯度、没有导数、没有"必须往低处走"的规则——
它靠的是"信息在种群中的传播"。

术语对照：

| 中文 | 英文 | 符号 |
|---|---|---|
| 粒子（一只鸟） | particle | $x_i$ |
| 位置 | position | $x_i$ |
| 速度 | velocity | $v_i$ |
| 个体历史最优 | personal best | $pbest_i$ |
| 全局历史最优 | global best | $gbest$ |

## 二、公式拆成三股力

标准 PSO 的速度更新式：

$$v_i^{t+1} = \underbrace{w \cdot v_i^{t}}_{\text{惯性}} + \underbrace{c_1 r_1 (pbest_i - x_i^{t})}_{\text{认知：奔向自己的经验}} + \underbrace{c_2 r_2 (gbest - x_i^{t})}_{\text{社会：奔向群体的经验}}$$

位置更新：

$$x_i^{t+1} = x_i^{t} + v_i^{t+1}$$

| 部件 | 物理含义 | 调大 | 调小 |
|---|---|---|---|
| $w$ 惯性权重 | 保持原方向的程度 | 探索强、难收敛、可能发散 | 收敛快、易早熟 |
| $c_1$ 认知系数 | 对"自己的经验"的信任 | 各自为战、多样性好、收敛慢 | 忽略个人经验 |
| $c_2$ 社会系数 | 对"群体经验"的信任 | 收敛极快、易被 gbest 带偏 | 信息不流通 |
| $r_1, r_2$ | 随机数，**逐粒子逐维独立** | 提供随机扰动，避免整群同步 | —— |

**$r_1, r_2$ 不是标量而是矩阵**，形状和位置一样。这是新手最容易写错的地方：
如果用一个标量，整个种群会"步调一致"，搜索能力大幅下降。

## 三、完整流程（伪代码）

```
初始化：
    每个粒子位置 x_i ~ U(lb, ub)
    每个粒子速度 v_i ~ 0 或 小随机
    pbest_i = x_i,  pbest_f_i = f(x_i)
    gbest   = argmin(pbest_f)

循环 t = 1 .. T:
    for 每个粒子 i:
        v_i = w·v_i + c1·r1·(pbest_i - x_i) + c2·r2·(gbest - x_i)
        v_i = clip(v_i, -vmax, +vmax)          ← 速度限幅，别省
        x_i = clip(x_i + v_i, lb, ub)          ← 边界处理
        f_i = f(x_i)                            ← 函数评价次数 +1
        if f_i < pbest_f_i:                     ← 只有更好才更新
            pbest_i, pbest_f_i = x_i, f_i
        if f_i < f(gbest):
            gbest = x_i
```

对应到 `tutorials/pso_step1_minimal.py` 的核心 3 行，以及 `algorithms/pso.py` 的第 65–78 行。

## 四、两个必须想通的设计（想不通就只是抄代码）

**Q1：为什么用 $pbest$ / $gbest$（历史最优），不用当前位置？**

因为 $f$ 在当前位置的值会被"当下一代"就过期了。$pbest$ 是**记忆**——
记忆让种群不丢失已经获得的信息，这是 PSO 相比"随机游走"的本质优势。
如果把公式里的 $pbest$ 换成 $x_i$，算法立刻退化成随机搜索。

**Q2：$gbest$ 是全局最优，整个种群都朝它飞，不就全体撞死在一个点上吗？**

会，这正是 PSO 的核心缺陷：**早熟收敛（premature convergence）**。
所以真实的 PSO 改进研究，一大半都在回答"怎么既用 $gbest$ 的好处，又不被它害死"：
拓扑结构、多子群、多样性监测、变异算子、gbest 随机选择……
**你未来的论文很可能就在这条线上。**

## 五、八个常见误解

1. ❌ **"PSO 是模仿鸟群，所以是仿生算法，有生物学依据。"**
   ✅ 它只是**受鸟群启发**的一个数学模型，别在论文里编生物学故事。

2. ❌ **"收敛曲线应该是曲线下降。"**
   ✅ 记录的是**历史最优**，所以一定**单调不增**。如果你的曲线上下波动，
   说明你记录的是当前位置，写错了。

3. ❌ **"迭代到后面一定会找到全局最优。"**
   ✅ 不会。PSO 没有全局收敛保证（这不是遗传算法那种有收敛性证明的东西）。
   "收敛"只意味着**种群挤到一起了**，那个点可能是个很差的局部最优。

4. ❌ **"参数越大越强。"**
   ✅ 见下面的实验数据，$c_1=c_2=2.0$ 配较大的 $w$ 反而更差。

5. ❌ **"速度不需要限幅。"**
   ✅ 不限幅时速度会无界增长，粒子被边界反复"拍在墙上"，根本收敛不了。
   **这是你仓库原版 PSO 的实际缺陷。**

6. ❌ **"种群越大越好。"**
   ✅ FES 预算固定时，种群规模 N 与迭代代数 T 此消彼长（N×T = FES）。
   太大来不及精修，太小采样不足。

7. ❌ **"PSO 只能做连续优化。"**
   ✅ 二进制 PSO（特征选择）、置换 PSO（TSP/调度）、多目标 PSO（MOPSO）都是成熟方向。

8. ❌ **"惯性权重线性递减（0.9→0.4）一定比固定权重好。"**
   ✅ 这是一个流传极广的**启发式经验**，不是定理。我实测下来（Rastrigin 30 维，
   15000 FES，5 次运行）：固定 $w{=}0.4$ 得 5.08e+01，线性递减 0.9→0.4 得 6.75e+01
   —— **递减反而更差**。
   原因不难理解：递减把"后期的小步精修"和"前期的探索"绑死在同一条时间线上，
   而问题未必需要这种时间分配。
   **这一条是本指南最重要的思维方式：不要继承结论，要复现结论。**
   你在读论文时看到的每一个"经验取值"，都应该先问："在我的问题上测过了吗？"

## 六、你仓库原版 PSO 的实测缺陷（这是你的第一课）

**先给结论：原版 PSO 是坏的，而且是三处互相独立的问题。**
在 30 维平移+旋转 Sphere 上，5 次独立运行（`max_fes=20000`）的逐项消融：

| 配置 | 均值（理论最优 0） | 相对上一行 |
|---|---|---|
| ① 冻结 gbest + 无限幅 + $c_1{=}c_2{=}2.0$（**原版**） | 4.31e+04 | —— |
| ② 修正 gbest + 无限幅 + $c_1{=}c_2{=}2.0$ | 1.44e+04 | 约 3 倍 |
| ③ 修正 gbest + 限幅 0.05 + $c_1{=}c_2{=}2.0$ | **4.92e-02** | 约 5.5 个数量级 |
| ④ 修正 gbest + 限幅 0.05 + Clerc 参数 | **3.54e-06** | 约 4 个数量级 |
| ⑤ 修正 gbest + 限幅 0.20 + Clerc 参数 | 3.70e+02 | 反而变差 |

### 三个缺陷，按影响排序

**1. 缺速度限幅**（②→③，好 5.5 个数量级）—— 影响最大。
没有限幅，速度会无界增长，粒子被边界反复截断，根本收敛不了。

**2. `gbest` 更新条件写错** —— 原代码是：

```python
g_idx = int(np.argmin(pbest_f))
if pbest_f[g_idx] < self._best_f:      # ← 这个条件永远为假
    gbest = pbest[g_idx].copy()
```

`self._best_f` 是"所有已评价点的最小值"，而 `min(pbest_f)` 恒等于它
（因为任何更优点都会成为某个粒子的 pbest）。**所以条件永远为假**：
全局最优被冻结在初始位置，整个种群一直飞向最开始那个最幸运的随机点。

→ 这是典型的**"看起来完全合理的错误代码"**：不报错、不崩溃，
只是让算法永远拿不到它该有的性能。你写代码时要格外警惕这一类 bug。

**3. 参数落在收敛区间外**（③→④，好 4 个数量级）—— $c_1{=}c_2{=}2.0$ 配 $w=0.9$。
换成 Clerc 那组（$w{=}0.729$, $c_1{=}c_2{=}1.4943$）即可。

**从 4.31e+04 到 3.54e-06：10 个数量级的提升，一个新算子都没有加。**

### 三个必须记住的教训

- **只在原始 Sphere 上测算法会害死你。** 原版在原始 Sphere 上"看起来还行"，
  只是因为最优值恰好在搜索区间的正中心；一平移就原形毕露。
  正式实验必须用**平移+旋转**版本，或者干脆上 CEC 基准集。
- **bug 比创新更能决定性能上限。** 如果基线本身是坏的，
  你报告的"提升"就是假的 —— 这属于误导性实验。
- **"看起来合理"不等于正确。** 唯一的检验手段是**消融实验**：
  把每个部件单独开/关，看它究竟贡献了多少。审稿人也一定会要这个。

> 关于收敛区间的理论：Clerc & Kennedy 2002（*The particle swarm — explosion,
> stability, and convergence in a multidimensional complex space*, IEEE TEC）
> 给出了稳定性分析。文献中常被引用的惯性权重收敛条件是
> $w < 1$ 且 $w > (c_1+c_2)/2 - 1$。按此，$c_1{=}c_2{=}2$ 时需要 $w>1$，
> 与 $w<1$ 矛盾——即这组参数本身处在非收敛区间。
> （该条件的表述在不同文献中略有差异，建议你读原文核对；但上表的**实测数据是确定的**。）
> Clerc 的收缩系数 $\chi = \frac{2}{|2-\varphi-\sqrt{\varphi^2-4\varphi}|}$，
> $\varphi = c_1+c_2 > 4$，当 $\varphi = 4.1$ 时 $\chi \approx 0.729$，
> 对应 $c_1 = c_2 = \chi\varphi/2 \approx 1.494$。

**⚠️ 学术诚信提醒**：拿一个"残废的基线算法"去对比你的改进算法，会让你的
"提升"显得很大——**但这是无效对比，属于误导性实验**。
审稿人一旦发现，直接拒稿。**基线必须调到它自己的合理水平。**

## 七、参数怎么选（工程建议）

| 参数 | 建议 | 说明 |
|---|---|---|
| $w$ | 0.729（固定）或按问题实测 | Clerc 值稳妥；"线性递减一定更好"是**未经检验的说法**，见下方实测 |
| $c_1, c_2$ | 1.4943 / 1.4943（稳妥）；或 2.0 / 2.0（常见但需配合限幅） | 两者大致相当，$c_1=0$ 会明显变差 |
| $vmax$ | **必须实测**；本仓库默认 0.05 | 不限幅必炸；文献常引用的 10%~20% 实测未必好 |
| 种群规模 | 30~50（常规）；大规模问题 100~200 | 记住 N×T = FES，实测 pop=200 最差 |
| 初始速度 | 0 ~ 0.1×range 的小随机 | 0.3×range 会明显变差，别设太大 |
| 停止条件 | **固定 FES（不是固定代数）** | 不同算法种群规模不同，只比代数不公平 |

### 限幅取值实测（Clerc 参数，30 维，30000 FES，10 次独立运行）

| vmax_ratio | 无限幅 | 0.02 | 0.05 | 0.1 | 0.2 | 0.5 |
|---|---|---|---|---|---|---|
| Sphere(平移) | 5.73e+03 | 1.71e-09 | **1.46e-10** | 2.78e-10 | 3.15e+02 | 1.50e+03 |
| Rastrigin | 1.01e+02 | 3.03e+01 | **2.38e+01** | 3.69e+01 | 6.33e+01 | 7.38e+01 |
| Ackley | 1.31e+00 | 1.31e+00 | **7.69e-01** | 7.81e-01 | 9.90e-01 | 1.38e+00 |

**怎么读这张表：** 不限幅在任何问题上都最差；0.05 在三个问题上都最好。
但**不要**由此得出"0.05 是普适最优"——它只说明**"文献里常引用的 10%~20% 未必好，
必须自己在问题上测"**。这个"没有普适最优参数"的空隙，本身就是论文选题
（见下方 P2、P5）。

## 十、调试清单（代码跑不对时按顺序查）

- [ ] 目标函数返回的是 float 而不是数组？
- [ ] `pbest` 更新用的是「更小才更新」（`f < pbest_f`）而不是无条件覆盖？
- [ ] 随机数种子固定了吗？两次运行结果一致吗？
- [ ] `vmax` 设了吗？单位是"搜索范围的比例"还是绝对值？
- [ ] 边界处理是截断还是反弹？截断会让粒子"贴在墙上"，是否合适？
- [ ] 收敛曲线记录的是历史最优（单调）还是当前位置（会波动）？
- [ ] 评价次数统计对吗？（每次 `f(x)` 都要计数）
- [ ] 不同算法比较时，FES 预算是否一致？
- [ ] 换一个测试函数（例如平移版）结果是否依然合理？
- [ ] 30 次独立运行的统计结果，而不是单次最好结果？
